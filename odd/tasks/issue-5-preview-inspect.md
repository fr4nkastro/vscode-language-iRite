# Issue #5 — screen preview inspection upgrades (phase 1, read-only)

Objective: upgrade `iRite: Preview Screens` (`irite.previewScreens`) with a 7"/12" panel selector, a widget list synced with the canvas, hide/show, preview-only z-order and richer code links, and fix the z-index bug that hid widgets when a full-screen background was selected. Nothing is ever written to `.rev`. Branch `feat/issue-5-preview-inspect` (chain: `feat/visualizers` -> `feat/issue-2-db-access` -> `feat/issue-3-sfc-layout` -> `feat/issue-4-callmap` -> this one). Delivery: local work-unit commits only (no push, no PR). Test runner: vitest (`npm test`), `npm run typecheck`, `npm run compile`.

## Specs
- S1 — Bug: "Selection must be an outline overlay that does not change paint order." / "Selecting `img7` on DOLE screen 1 keeps `imLoad` (id 130) visible."
- S2 — "Size selector: `7" 800x480` (default) and `12" 1280x800`." / "`.rev` coordinates are authored for 7"; on 12" widgets scale automatically (no manual step)." / "Switching to 12" rescales every widget without user input; switching back restores 7"."
- S3 — "Open decision: 1280/800 = 1.6 but 800/480 = 1.667 — uniform scale 1.6 with a 32 px band, or per-axis scale? Confirm against a real 12" unit." and "Open decision: the current 800x388 canvas assumes a 92 px header. Confirm what the 1280 reserves on each panel." (decided by recommendation; real-unit confirmation stays open, see L3/L4).
- S4 — "Side panel (or below on narrow views) listing every widget of the active screen: id, type, alias, x/y/w/h, reference count." / "Selecting a row selects the widget on the canvas and vice versa." / "Every widget of a screen appears in the list; list and canvas selection stay in sync."
- S5 — "Toggle visibility per widget (eye icon in the list) to reveal what sits behind overlapping widgets. Show all / reset." / "Preview-only state, persisted per webview (`vscode.setState`), never written to `.rev`." / "Hidden widgets stay hidden across re-renders of the same panel and reset on demand."
- S6 — "\"Send to back\" / \"Bring to front\" as a local view override, to inspect stacking. Clearly marked as not saved."
- S7 — "Keep current references (alias in call args and `if/elsif` conditions) and group them by routine and file." / "Include references outside calls (assignments, plain comparisons) so aliases like `lblPlaca` always resolve." / "Every reference is a clickable `file:line` link (already supported by the `open` message)." / "Clicking a reference opens the file at that line."
- S8 — "Resolve screen names from `UiScreen` / `uiLoadSettingsUi` and show the per-screen click handler (e.g. `WidgetClicked` → `handlerScreenPlateEntry`) as the entry point of that screen."
- S9 — "Pure logic (scaling, reference index, screen-name resolution) covered by vitest in `test/preview/`." Plus: "Reference-index changes affect `src/docs` (it consumes `WidgetView`)" — docs and call map must keep working.

## Log
- L1 (user, original request): GitHub issue #5 "feat(preview): screen preview inspection upgrades (phase 1, read-only)" — https://github.com/fr4nkastro/vscode-language-iRite/issues/5 . The user gave green light to pick the most recommended option for every open decision.
- L2 (decision, z-index): hover and selection are two `pointer-events:none` overlay boxes per screen (`.ovl.hov`, `.ovl.sel`, z-index above every widget rank) positioned from the widget's own box; widgets never get a class that changes paint order. Done as its own `fix` commit.
- L3 (decision, 12" scaling): uniform scale `min(1280/800, 800/480) = 1.6`, per-axis scale rejected because it would stretch authored proportions (circular symbols, aspect of images). The vertical remainder (32 px) is a hatched letterbox band under the content, flagged "assumption" in its tooltip. Unconfirmed on a real 12" unit.
- L4 (decision, header): the 7" header stays 92 px (observed on DOLE, 800x388 usable). The 12" header is 92 x 1.6 = 147.2 px: the only value for which header + scaled content + 32 px band = 800, i.e. the simplest model consistent with the issue's "1.6 with a 32 px band". It is one named constant (`PANELS["12"].headerHeight` in `src/preview/panels.ts`) documented as unconfirmed.
- L5 (decision, references): the parser records every identifier use per routine (`idRefs`, one entry per name and line, excluding call names, fields after a dot and string contents), plus numeric literal assignments (`literalAssigns`) and the closing line of multi-line calls (`IriteCall.endLine`). A reference that is not already explained by a call (arguments, same line span) becomes a `(reference)`; call-based `callee` and `(condition)` labels are unchanged, so docs keep their old rows and gain the extra ones.
- L6 (decision, screen names): `UiScreen` record fields x assignments `<var>.<Field> := N` in `uiLoadSettingsUi` (any routine when it does not exist). Several fields can share a number (DOLE: Error and Notification = 6); both are shown. The entry point is the call under a `WidgetClicked` branch whose condition ends in `.Field`; only calls to declared project routines count.
- L7 (decision, list/state): list rows are rendered by the extension (pure `buildWidgetRows`), the page script only wires selection. Hide/z-order are per screen; state is `{screen, panel, hidden, order}`, sanitized by `previewState.sanitize` in the extension and in the page, re-embedded on every re-render and also kept with `vscode.setState` (same belt-and-braces as #4).
- L8 (decision, z-order model): per screen two ordered lists (`back`, `front`); the latest "send to back" is bottom-most, the latest "bring to front" top-most, everything else keeps id order. Paint rank is applied as z-index on widgets only; overlays always sit above.

For T2-T6 the tests were written before the implementation but were first run together with it (module-missing was the RED); I did not re-run them against a stub.
